# SMS TEST v3.1 — Android

Flet-приложение для проверки собственных SMS API. Отправляет POST-запросы с полем формы `phone` прямо из приложения, показывает HTTP-код и сохраняет URL-профили и выбранный профиль после выхода.

## Что исправлено в v3.1

- Ввод номера с кодом страны **без `+`**: `79991234567`; вариант `+79991234567` тоже принимается. Номер проверяется через `phonenumbers`.
- На главной странице есть настройка **«Передавать в поле phone только цифры (без +)»**. Когда она выключена, номер отправляется в международном формате с `+`; когда включена, — без `+`. Настройка сохраняется.
- Исправлено сохранение профилей: `SharedPreferences` получает **JSON-строку**, а не неподдерживаемый список словарей. Сохраняются полные HTTPS URL, названия и выбранный профиль.
- История статусов сохраняется в совместимом формате, без номера телефона и параметров URL.
- Профили можно добавлять, выбирать и удалять; максимум 20 профилей. Отдельный API-ключ не сохраняется.
- Встроенная отправка только для API, на которые у вас есть разрешение. Страницы авторизации/OAuth остаются в браузере; автоматизированных запросов кодов входа нет.
- По умолчанию одна отправка; разрешено от 1 до 5 запросов, с паузой 3 секунды. При ответе HTTP 429 отправка прекращается.

## Как собрать APK через GitHub Actions

1. Распакуйте ZIP с исходниками.
2. В существующем GitHub-репозитории обновите файлы проекта (или создайте приватный репозиторий). Загружайте **содержимое папки** `SMS_TEST_v3`, чтобы `pyproject.toml` находился в корне репозитория, а `.github/workflows/build-android.yml` — внутри `.github/workflows`.
3. Откройте **Actions** → **Build Android APK** → **Run workflow** → зелёную кнопку подтверждения запуска.
4. После статуса **Success** откройте запуск, скачайте артефакт **SMS-TEST-v3.1-Android** и распакуйте архив до APK.
5. Установите APK на телефон и откройте приложение.

Если новая сборка не устанавливается поверх старой (например, разная подпись APK), **не удаляйте старую версию до переписывания сохранённых ссылок**. Android удаляет данные SharedPreferences при удалении приложения. При обычном закрытии приложения профили остаются.

## Как использовать

1. На вкладке **+ Ссылки** добавьте имя и полный HTTPS URL своего SMS API, нажмите **+ Сохранить URL**. Длинные строки с `?`, `&`, `=` сохраняются без изменений.
2. Вернитесь на **Главную**, введите номер `79991234567` или `+79991234567`.
3. Если API принимает `phone=79991234567`, включите **«Передавать в поле phone только цифры (без +)»**. Если принимает `phone=+79991234567`, оставьте настройку выключенной.
4. Подтвердите право тестирования выбранного номера и API и нажмите **Отправить POST**. Запрос отправляется из приложения, без браузера.
5. Результат отражает ответ API. HTTP 2xx означает принятие запроса сервером, но не доказывает доставку SMS.

**Пример формата POST:** `https://api.example.com/sms/send`, поле формы `phone=79991234567`. Для API с Bearer-токеном введите его в поле ключа на текущий сеанс. URL проверки доставки необязателен и зависит от API.

## Важные ограничения

- Отправка на ссылки входа/OAuth и вызов чужих кодов авторизации не поддерживаются. Такие ссылки можно сохранить и открыть в браузере.
- Для работы API необходим HTTPS; редиректы при отправке не выполняются.
- Не сохраняйте пароль, Bearer-токен или иные секреты в строке URL: профиль хранится на устройстве без отдельного шифрования в приложении.
- После удаления приложения Android обычно удаляет его настройки. Хранение после **закрытия/повторного запуска** поддерживается, восстановление после удаления приложения — нет.

## Локальная сборка Windows (если нужна)

При настроенных Flutter, Android SDK и JDK:

```powershell
cd "D:\download\SMS_TEST_v3_Android_Source_FIX2\SMS_TEST_v3"
& "C:\Users\msi\AppData\Local\Python\pythoncore-3.14-64\Scripts\flet.exe" build apk --yes --python-version 3.13
```

На вашем компьютере ранее были тайм-ауты `pypi.flet.dev`, поэтому **предпочтительнее GitHub Actions**. Локальные пути приведены как пример прежней настройки и должны соответствовать фактическому расположению обновлённых файлов.

## Тестирование Python-части

С установленными `requests` и `phonenumbers`:

```bash
python -m unittest discover -s tests -v
```

Архив содержит только исходники и настройки CI; готовый APK формируется GitHub Actions.
